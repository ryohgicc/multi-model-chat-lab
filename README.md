# Multi Model Chat Lab

本机运行的多模型对话调试工作台。一次向最多 5 个模型发送同一条消息，并排查看回复、耗时、Token 用量和估算费用。适合比较模型表现、调试系统 Prompt，以及观察上下文压缩效果。

界面采用暖纸色背景、白色细边框面板和蓝色主操作，保留原有并排工作台布局。

## 功能

- 支持 OpenAI 兼容、Anthropic 兼容、Gemini 原生协议和自定义完整接口 URL 四种接入方式；模型可单独选择流式或非流式响应，并测试连接。
- 支持添加多个模型，在 1–5 个面板中并发对话。单个模型请求失败不会中断其他面板。
- 每个对话窗口独立保存历史；各模型只接收共同的用户消息和自己的历史回复。切换面板模型后从新上下文开始。
- 每轮可编辑系统 Prompt 和最近 0–100 轮上下文；支持 `${userInputPrevious}`、`${aiOutputPrevious}`、`${userInputlatest}`、`${memory}`、`${summary}`、`${currentTime}` 变量，并可预览替换值。
- 支持按模型分别手动或定期压缩上下文，生成 `memory` 和 `summary` 供后续 Prompt 使用。
- 显示回复总耗时、首字耗时、接口返回的 Token 用量，以及基于自填价格计算的费用。接口未返回用量时标记统计不完整。
- 支持复制单条回复，或从每个面板顶部复制该模型的完整 Markdown 对话记录；还支持失败重试和欢迎语生成。统一连接配置、模型价格与对话保存在当前浏览器。
- 支持“模型点评”：工作空间统一设置测评模型和 Prompt，选择一个对话窗口后，并发点评各当前模型面板的完整 Markdown 记录。结果按对话窗口和面板保存在当前浏览器，再次分析会覆盖旧结果。
- 工作空间侧栏新增“表达评估测试”：固定陪练、回复和测评模型，勾选多个评估模型，在相同对话输入下逐轮比较评估效果并收集评分与结论。
- 工作空间侧栏提供独立的“回复效果测试”页面：从全部已配置模型中选择任意数量的陪练模型，并配置回复模型和测评模型，填写各自 Prompt，并在测试内容和测试目的两个列表中逐行输入，一行组成一组用例；默认每个陪练模型创建独立测试对话，不承接原对话历史，均逐组测试；每次运行创建独立任务，单击任务查看按陪练模型分组的结果表；每个模型分别显示“通过”“不通过”“无法判断”的数量与比例；通过率和不通过率以“通过＋不通过”为分母，无法判断占比以总用例数为分母。解析失败和未完成用例不计入这三类；明细表默认收起，可按模型独立展开、收起并按 type 筛选；每个模型可分别复制“不通过”和“无法判断”的完整结果行，输出为含全部表格列的 Markdown 表格。结果表展示陪练初始回复、回复 AI 输入、陪练再次回复、测评原文以及测评返回的 `type`、`score` 和 `analysis`；模型摘要仅对已评分且通过的用例统计平均分，并统计成功生成的陪练再次回复的平均耗时。
- 工作空间侧栏提供“食谱生成测试”：选择多个计划 AI 和一个测评 AI，输入逐行测评内容。每个计划 AI 针对每条内容生成食谱，测评 AI 再读取该食谱并返回 `score` 与 `conclusion`。
- 工作空间侧栏提供“课程生成调试器”：填写课程生成 Prompt、分类和主题，逐行输入场景并选择一个模型。每个场景独立请求，`scene_name` 为“分类-主题-场景”，`theme_scene_list` 自动由全部场景组成；结果按输入顺序汇总，并将角色、主题、难度和任务分区展示。可查看原始 JSON 与请求返回、复制结果 JSON、终止任务，表单和历史保存在当前浏览器。
- 每个模型面板底部提供折叠的独立对话入口；展开后可只向当前模型发送消息，不影响其他面板。
- 可切换沉浸模式，将模型返回的单个 JSON 对象或数组中的每个对象显示为独立对话气泡，区分普通回复、纠错和话题转换；无法解析时显示原文。

## 环境要求

- Node.js 22 或更新版本
- npm
- 至少一个可用的模型接口、统一 API Key、Base URL、接入方式和流式设置，以及模型名称和价格

## 快速开始

```bash
git clone https://github.com/ryohgicc/multi-model-chat-lab.git
cd multi-model-chat-lab
npm install
npm run dev
```

打开终端显示的 Vite 地址，默认是 <http://127.0.0.1:5173>。开发命令会同时启动网页和本机接口服务。

在「模型与设置」中选择模式。NewAPI 模式下，“管理 Key”只填写共用的 API Key 和 Base URL；“新增模型”只填写模型名称、接入方式及输入/输出价格。自由模式下，每个模型单独填写完整接入信息。模型名称会作为接口的 model 参数；保存后可在工作台面板顶部选择模型。

在「课程生成调试器」中选择生成模型，填写 Prompt、分类、主题，再逐行输入场景。分类和主题各填一次，发送给模型的 `scene_name` 由“分类-主题-场景”拼成；`theme_scene_list` 自动由非空场景行组成 JSON 字符串数组，对所有请求共用。Prompt 可引用 `${scene_name}` 与 `${theme_scene_list}`；每个场景单独发送结构化用户消息，返回值按 JSON 对象解析。结果页可展开查看实际请求和返回；当上游成功响应却没有可显示文本时，会保留上游 JSON 供排查。格式错误不会阻止后续场景生成。

在侧栏打开「模型点评」，选择已配置的测评模型并填写测评 Prompt，再选择对话窗口执行分析。每个有记录的当前模型面板会把与面板右上角“复制”按钮相同的 Markdown 内容作为用户消息，连同测评 Prompt 发给测评模型；各面板并发请求，结果按对话面板顺序并排显示，窄屏可横向滚动。失败的点评会显示错误，可再次执行分析。测评模型和 Prompt 是工作空间设置，点评结果只保存在当前浏览器。

在工作空间侧栏打开「回复效果测试」。回复效果测试默认按每个陪练模型创建独立测试对话，不承接所选窗口或其他模型的历史；使用所选对话的 Prompt 和欢迎语指令先生成该模型的打招呼，再将打招呼作为首组陪练输入。也可切换为复用所选对话上下文；测试消息会写入新建的测试对话，不写入原对话。两个测评集列表的行数需一致，空行会提示修正。回复模型收到测试内容及该模型上一条有效回复；测评模型收到回复输入、对应陪练回复和测试目的。回复和测评 Prompt 由用户填写，两者都可用 `${testContent}` 和 `${testPurpose}` 引用当前行的测试内容与测试目的，`${aiinputContent}` 引用本组开始时陪练 AI 的上一条有效回复，`${aioutputContent}` 引用回复 AI 对它生成的内容，`${aiinputContent2}` 引用陪练 AI 再次生成的回复。测评模型会收到 `${aiinputContent}`、`${aioutputContent}`、`${aiinputContent2}`、`${testPurpose}` 四个值；结果表的“陪练 AI 初始回复”展示 `${aiinputContent}`，“陪练 AI 再次回复”展示 `${aiinputContent2}`。回复 AI 运行时后两个值为空。测评回复可为含字符串 `type`、`analysis` 和可选 `score` 的 JSON 对象；新评分规则要求 `score` 为 0–100 的整数，通过给 60–100 分，不通过给 0 分，无法判断给 null。旧任务没有分数时显示为未评分。测评解析会容错处理分析文本中的未转义双引号、多余引号转义和换行，保留原始输出；刷新页面时自动重新解析历史格式错误，能恢复的结果重新计入统计。支持提取带前后说明的测评 JSON 代码块，以及明确标注“结论 / 判定”的 Markdown 结果；没有分数时仅计入通过率，不补造评分。未给出明确判定的续聊或改写回复、缺失字段、截断输出和违规分数仍显示测评格式错误，不判成陪练不通过。测评请求会自动补充评判对象、JSON 格式和数据指令隔离要求。各陪练模型并发、各用例顺序执行；表单内容和每次测试任务会自动保存在当前浏览器，切换页面或刷新后可恢复；测试对话和结果也仅存于当前浏览器，不写入原对话。同一浏览器的标签页会同步任务进度和终止操作；点击终止会取消进行中的请求并保留已完成结果。所选对话没有已发送轮次时，使用当前对话 Prompt 让陪练模型先打招呼；招呼作为首组的 `${aiinputContent}`，随后继续正常测试。

### 回复效果测试注意事项

- 陪练 AI 负责模拟对话，回复 AI 负责生成待测回复，测评 AI 负责判定回复是否符合标准。三者角色不同，Prompt 中要写清楚评价对象。
- 测试内容和测试目的必须逐行对应，不能缺行；一次测试请求数量约为陪练模型数量 × 测试内容条数。
- 测评 Prompt 建议要求返回 JSON，包含 `type`、`analysis`、`score`。`type` 只能是“通过”“不通过”或“无法判断”；通过分数为 60–100，不通过为 0，无法判断为 null。
- `${aiinputContent}`、`${aioutputContent}`、`${aiinputContent2}` 分别表示陪练初始回复、回复 AI 输出和陪练再次回复；尚未生成的变量为空。

### 表达评估测试注意事项

- 陪练 AI 生成对话输入，回复 AI 生成待评回复，多个评估 AI 分别点评，固定测评 AI 汇总点评质量。
- 测评 Prompt 必须返回 JSON，并包含数字 `score` 与非空字符串 `conclusion`，例如 `{"score": 80, "conclusion": "点评具体且有依据"}`。
- `analysisContent` 是评估 AI 的点评，测评 AI 评价的是点评质量，不是继续生成对话。
- 测试内容和测试目的按行一一对应；每轮使用一条用例，评估模型数量越多，请求数量越大。

在同一级侧栏打开「表达评估测试」，配置四个角色：选择一个陪练模型、一个回复模型、一个测评模型，并勾选一个或多个评估模型。默认选择首个非测试对话作为“对话 Prompt 来源”，也可切换来源。陪练 Prompt 按回复效果测试相同规则读取所选对话最近一轮 Prompt（无轮次时使用对话 Prompt 草稿），欢迎语指令读取该对话设置；两项只读展示，需要修改时在源对话中编辑。开始测试时保存来源与实际使用的两项设置快照，不承接源对话历史。回复、评估、测评三份 Prompt 仍在此填写。评估 Prompt 由所选评估模型共用。填写“测试内容”和“测试目的”两个逐行对应的测评集列表，行数需一致且不允许中间缺项。回复轮数自动等于有效用例数量，无需手动设置。每次测试新建一段独立对话，按列表顺序每轮使用一条用例，各轮连续承接历史。

### 食谱生成测试使用教程

1. 先在「模型与设置」中配置至少两个模型。进入侧栏「食谱生成测试」，在“计划 AI”中勾选要比较的模型，在“测评 AI”中选择一个专门负责打分的模型。
2. 填写“计划 Prompt”。使用 `${testContent}` 引用当前测评内容，例如：`根据以下需求生成一份可执行食谱：${testContent}`。每个计划 AI 都会收到同一条内容，但会独立生成结果。
3. 填写“测评 Prompt”。使用 `${testContent}` 引用需求，使用 `${planOutput}` 引用计划 AI 的完整输出，并明确评分标准。建议要求测评 AI 只返回：`{"score": 0-100, "conclusion": "评价"}`。
4. 在“测评内容”中每行写一条需求，例如“为两人制作低脂高蛋白晚餐”。每行是一组独立用例，不需要填写测试目的。
5. 点击“开始测试”。系统按“测评内容 × 计划 AI”执行：计划 AI 先生成食谱，测评 AI 再逐条评估。任务列表会显示进度，点击任务可查看明细。
6. 结果表中的 `score` 是测评 AI 返回的数字分数，`conclusion` 是文字评价；如果测评 AI 没有返回有效 JSON，结果会保留原文并显示错误，方便修改 Prompt 后重新测试。

食谱测试的工作流可以概括为：

```text
测评内容 → 计划 AI 生成食谱 → 测评 AI 读取食谱并评分 → 结果表（score / conclusion）
```

计划 Prompt 决定“怎么生成”，测评 Prompt 决定“按什么标准评价”。

#### 食谱测试注意事项

- 测评 Prompt 必须明确要求返回 JSON 对象，并包含两个字段：`score` 和 `conclusion`。`score` 必须是数字，`conclusion` 必须是非空字符串。推荐格式：`{"score": 85, "conclusion": "食材和步骤完整，营养搭配合理"}`。
- 不要让测评 AI 只返回自然语言、Markdown 表格或缺少字段的结果，否则该条会保留原文并标记为测评格式错误。
- `${testContent}` 表示当前测评内容，`${planOutput}` 表示计划 AI 的完整输出，变量名需要完全一致。
- 测评内容按换行拆分，每个非空行是一条独立用例；一次测试的请求数量等于“计划 AI 数量 × 测评内容条数”。
- 测评 AI 只负责评价计划输出。应在测评 Prompt 中写清准确性、完整性、可执行性、营养合理性等评分标准。
多个计划 AI 共用同一批测评内容，测评 AI 固定为一个，便于横向比较不同计划模型的生成质量。

表达评估测试按以下顺序运行：

1. 陪练 AI 先按 Prompt 和欢迎语指令打招呼，作为首轮 `${aiinputContent}`；回复 AI 同时接收当前行 `${testContent}`（测试内容）和 `${testPurpose}`（测试目的），据此生成 `${aioutputContent}`。同一轮只生成一份对话内容，所有评估模型使用相同输入。
2. 各评估 AI 分别接收 `${aiinputContent}`、`${aioutputContent}` 和评估 Prompt，生成各自针对回复的点评 `${analysisContent}`。评估 AI 也会收到当前行测试内容和测试目的。
3. 固定的测评 AI 分别接收本轮输入、回复、每个评估模型的 `${analysisContent}`、当前行 `${testContent}` 和 `${testPurpose}`，以及测评 Prompt，返回 JSON：`{"score": 80, "conclusion": "结论说明"}`。`score` 必须为有限数字，`conclusion` 必须为非空字符串；评分标准由测评 Prompt 指定。
4. 如有下一轮，陪练 AI 接收本轮回复并承接本次测试的对话历史，生成下一轮输入；长对话最多发送最近 100 条消息，以符合接口限制。每轮收集所有评估和测评结果，第 N 轮使用第 N 条用例，最终按“轮次（用例）× 评估模型”显示完整列表，结果总数为用例数量乘以评估模型数量。

回复、评估、测评 Prompt 支持 `${aiinputContent}`、`${aioutputContent}`、`${round}`、`${testContent}`、`${testPurpose}`，以及评估点评 `${analysisContent}`；旧变量 `${output}` 和 `${evaluationResult}` 继续作为点评的别名。以上变量兼容 `$${变量名}` 写法，尚未生成的值为空。请求同时以结构化消息提供相应数据。结果包括当前行测试内容、测试目的、输入、回复、评估点评、测评原文、评分、结论和错误，并按评估模型计算有效评分的平均分。可以查看任务 Prompt 快照、复制完整结果 JSON。表单草稿与历史任务分别自动保存在当前浏览器，优先恢复独立草稿，并兼容旧版合并存储的配置。同一浏览器、同一访问地址的新窗口会恢复已保存的表单，窗口切回或页面重新可见时重新读取最新内容。历史结果保存失败时仍会单独尝试保存表单，分别提示表单与结果的保存状态。切换页面后继续运行；刷新后保留已完成结果，原运行在心跳过期后标为已中断，不自动重发请求。中断任务在列表和详情中显示已记录的原因；运行页面失联会标明心跳过期，旧任务没有记录时明确提示原因未记录。支持跨标签页同步进度与终止；终止会取消当前请求并保留已完成结果。单个评估或测评失败会记录错误并继续其他模型与后续轮次；陪练或回复失败会停止后续对话轮次，保留已完成结果。临时请求失败最多重试两次。浏览器存储失败时会提示复制备份，当前页面仍保留内存结果。

生产构建及本机运行：

```bash
npm run build
npm start
```

打开 <http://127.0.0.1:3001>。服务仅监听 `127.0.0.1`。

表达评估的表单与任务现优先写入当前访问地址的 IndexedDB（数据库 `model-studio-expression`），不再占用 localStorage 的容量。旧版 localStorage 草稿与历史记录仍可读取，原数据不会被删除。请等到“表单已自动保存”后再刷新；“正在保存”表示事务尚未完成。如果两种存储均不可用，页面显示具体异常，请保留窗口并下载表单备份。不同浏览器或不同访问地址的存储仍不互通。

```bash
PORT=3002 npm run start:lan
```

如果原有开发页仍在运行，就在主机原有浏览器打开 <http://127.0.0.1:5173>；否则在主机打开 <http://localhost:3002> 并先配置模型。进入「模型与设置」，点击「一键发布所有 Prompt 和本地设置」。这一步会把全部模型参数和 API Key、每个对话的名称、当前 Prompt、欢迎语、上下文轮数、压缩 Prompt、压缩读取最近轮数、自动压缩间隔、面板模型选择，以及工作空间的显示模式、面板数量、测评模型和测评 Prompt 写入主机的 `data/shared-models.json`。其他设备刷新后会收到各个对话的设置；重复发布会更新已同步的对话，保留设备上的历史记录。首次访问的局域网设备会默认打开当前选中的本地对话。历史消息和点评结果不会复制。其他设备连接同一局域网后，打开 `http://主机局域网IP:3002`；例如主机 IP 是 `10.0.9.99` 时，访问 <http://10.0.9.99:3002>。Mac 可用 `ipconfig getifaddr en0` 查看 Wi-Fi 地址。

局域网设备也可以在「模型点评」中选择主机已发布的模型并填写测评 Prompt。主机未发布点评设置时，设备自己的选择保存在当前浏览器，刷新后继续使用；主机发布的测评模型和 Prompt 会在刷新时同步。

其他设备会自动读取已发布的配置，无需重复填写。局域网设备仅支持 NewAPI 模式，需要先在“模型与设置”填写本机 API Key；填写后才会显示新增/管理模型按钮。API Key 只保存在主机，不会返回给其他设备；各设备的聊天记录仍各自保存在浏览器。请只在可信局域网使用：任何能访问这个地址的设备都可以调用已发布的模型，产生你的 API 费用。停止服务请在运行终端按 Ctrl+C。若无法访问，检查设备是否同网段，以及主机防火墙是否允许 3002 端口。

## Cloudflare 网页

当前线上地址：<https://multi-model-chat-lab.1049250335.workers.dev>。网页和 `/api` 由同一个 Worker 提供，KV 保存共享的模型参数、Prompt 和工作台设置；**KV 不保存 API Key**。访问者在自己的浏览器填写 API Key，聊天请求会带该 Key 发给 Worker，再由 Worker 请求已发布模型对应的接口。聊天记录与测试结果仍留在各自浏览器。知道链接的人可以查看已发布设置，使用功能需自己提供 Key。

本机 `.env.cloud` 保存云端地址、发布令牌和可选的本机 HTTP 代理；该文件被 Git 忽略。启动带云端发布能力的本机开发页：

```bash
npm run dev:cloud
```

在本机 <http://127.0.0.1:5173> 编辑后，点击「一键发布所有 Prompt 和本地设置」。本机服务会先保存原有本机配置，再从云端发布请求中去掉所有 API Key，通过发布令牌更新 KV。页面提示发布成功后可刷新线上网页确认。若本机访问 `workers.dev` 需要代理，在 `.env.cloud` 中设置 `CLOUD_PUBLISH_PROXY=http://127.0.0.1:8888`；代理端口按自己的环境修改。请勿分享 `.env.cloud` 或发布令牌。

后续更新线上代码：

```bash
npm run deploy:cf
```

这会构建并发布代码与静态资源；共享设置保存在 KV，不会随代码发布清空。首次部署需先登录 Wrangler、创建 KV 命名空间、配置 `wrangler.jsonc` 的绑定，并以 `wrangler secret put PUBLISH_TOKEN` 设置发布令牌。

## 接口地址

| 接入方式 | 地址示例 | 实际请求 |
| --- | --- | --- |
| OpenAI 兼容 | `https://api.openai.com/v1` | 自动追加 `/chat/completions` |
| Anthropic 兼容 | `https://api.anthropic.com/v1` | 自动追加 `/messages` |
| Gemini 原生协议 | `https://generativelanguage.googleapis.com/v1beta` | 自动追加 `/models/{模型 ID}:generateContent`；流式请求使用 `:streamGenerateContent?alt=sse` |
| JEV 兼容协议 | NewAPI Base URL 前缀 | 自动追加 `/typesafe/v1/systemone`；请求体使用 `model`、`state`、`questions`，系统 Prompt 填写 questions JSON；非流式返回显示为 JSON |
| 自定义直接请求 | `https://example.com/v1/chat/completions` | 直接向填写的完整 URL 发送 POST |

自定义模式使用 OpenAI 兼容的请求与响应格式，适合已有完整聊天接口 URL 的网关。它不支持任意 HTTP 请求模板。默认启用流式响应；如果接口不支持，可在模型设置中关闭。

## Prompt 与上下文

每轮系统 Prompt 可独立编辑，新一轮默认沿用上一轮。上下文轮数默认 10，设为 0 时只发送本轮用户消息。变量在每个模型发出请求前按该模型自己的上下文替换：

| 变量 | 含义 |
| --- | --- |
| `${userInputPrevious}` | 上一轮用户消息 |
| `${aiOutputPrevious}` | 该模型上一轮回复 |
| `${userInputlatest}` | 本轮用户消息 |
| `${memory}` | 该模型最近一次压缩得到的长期记忆 |
| `${summary}` | 该模型最近一次压缩得到的近期摘要 |
| `${currentTime}` | 请求发送时的 UTC ISO 时间 |

压缩读取最近轮数和自动压缩间隔均默认 10 轮；自动压缩间隔设为 0 时关闭。压缩可手动触发，也可设置每隔若干轮自动触发。每个模型使用自己的对话记录独立生成结果；压缩失败不会覆盖已有记忆。手动「压缩全部对话」会处理已保存窗口中符合条件的模型对话。

## 数据与安全

默认本机模式下，模型配置、API Key、聊天记录、模型点评、回复效果测试表单与结果存储在当前浏览器的 `localStorage`。清除浏览器数据会删除这些内容。局域网模式下，主机发布的模型配置和 API Key 另存于 `data/shared-models.json`，聊天记录、点评、回复效果测试表单与结果仍只在各设备浏览器中。项目没有账号或云同步；请勿分享浏览器备份或主机上的配置文件。

Cloudflare 模式仅同步无密钥的共享设置。访问者的 API Key 保存在其浏览器，并经 Worker 转发给已发布的模型接口；访问者应确认信任这个 Worker 后再输入 Key。公开链接不提供身份验证，Prompt 和模型参数可被任何知道链接的人读取。
